The page

The studio's front page, Train card, opens it at /train.

Read nowevery source read at once, instead of on its interval (this machine 10 s, ssh 30 s)
Sourceswhere runs are read from and started on: this machine, and ssh logins
New runa run started on a source
the yellow stripwhat the studio is doing for the page: a run being started, a checkpoint being copied
runs, leftnewest first; a click on a card draws that run alone, the tick adds it beside the others, in the colour of its swatch; details opens the run
charts, rightone per metric, every ticked run on it; smoothing, x by step, hours or epochs, log axes for losses; hovering reads one step on every chart

The studio

cd ~/projects/pinkrab && source .venv/bin/activate
pinkrab-studio            # http://localhost:8730/

It answers this machine only. Runs do not need it: they keep training with the studio closed, and what they wrote meanwhile is read when it comes back.

Datasets

Every dataset under ~/pinkrab/datasets is offered, as the collect page's Convert or pinkrab-umi convert made it. A dataset is sent to a machine once; a dataset converted again is sent again, beside the old one, so a run still reading the old one is left alone.

A remote machine

A machine this studio trains on over ssh. What it needs follows from the PyTorch the lock pins - 2.11, built for CUDA 13.0:

systemLinux on x86_64, with python3, curl and an ssh login by key; the internet for the first setup
GPUNVIDIA, compute capability 7.5 or higher (Turing on): T4, RTX 20 / 30 / 40 / 50 series, A10, A100, A6000, L4, L40S, H100, H200, B200. Not Volta (V100) or older
driver580 or newer (CUDA 13.0). The CUDA toolkit need not be installed: PyTorch brings its own libraries
GPU memory8 GB or more: on two gripper cameras at batch 8, ACT peaks near 5.7 GB
CPU8 cores or more: decoding the video for each batch is the CPU's work, one core per loader worker
diskabout 15 GB for the Python, the venv and its download cache, then the datasets and the runs' checkpoints

test and New run check the GPU and the driver, and say what is short before anything is sent.

Adding one

Sources on the training page:

nameany, e.g. gpu-box
ssh, sftp or scp linethe host, port, user and key are taken from it: ssh -i ~/.ssh/id_ed25519 -p 22 user@gpu.example.com, or the line a cloud console hands out for a session
keyits path here, or the file itself - either way copied into ~/pinkrab/keys, readable by this user only, and used from there, so the original can be moved or deleted; never sent back to the page. Password logins are not used
runs are underwhere the machine keeps everything: ~/pinkrab-train. On a machine whose home directory is wiped between sessions, a directory on its persistent volume

Save and read, then test: its GPUs with their memory, driver and compute capability, its cores and free room, whether it is set up, what is running on it.

A machine given out by sessions - a new host or port each time - keeps its source: edit it with the new line. What was set up under its root is still there.

A new run

machinea source; its state is shown under it as soon as it is picked
datasetwith its episodes, frames and picture size
policyACT; batch 8 unless changed in batch
steps, log every, checkpoint every100 000, 50, 20 000 unless changed; a smaller log every is a denser chart at no cost to speed
namepolicy-dataset-date if left empty
more argumentsanything else lerobot-train takes, e.g. --policy.optimizer_lr=5e-5
copy each checkpoint hereon: every checkpoint is copied to this machine as it is saved

Start, and the strip says each step: the machine asked, the kit sent (the metrics logger, the setup script, this checkout's lock), the venv built or checked against the lock - minutes the first time on a machine, seconds after - the dataset sent if it is not there, the run started detached. It trains on with this page closed and the connection gone.

The run is lerobot-train started through pinkrab-train, the metrics logger: the same training, with a metrics.jsonl beside its checkpoints that this page reads. A run started with plain lerobot-train has none - it is only seen on the GPU, with no numbers (see Run states).

Run states

runningits files grew in the last five minutes
donetrained to its last step
stoppedstopped from here, or interrupted
failedended on an error, shown under it
quietno news for five minutes and no end: killed, or its machine gone

What is drawn is what pinkrab-train writes to a run's metrics.jsonl: the exact numbers, the checkpoints, the end. A run started with plain lerobot-train keeps no such file and has nothing to draw.

Each read also asks the source's nvidia-smi what is on its GPUs. A process no run here accounts for is listed under on a GPU, not recorded, by the --output_dir on its command line, with the GPU memory it holds; the source's chip counts it and the front page's Train card lists it. It is only seen to be there: no progress, no loss, no checkpoints.

Stop, resume, checkpoints

A run's details button opens it: where it runs, its terminal, its configuration, its checkpoints. A click outside the box closes it.

Stoppressed twice; the run is sent SIGTERM and ends stopped
Resumefrom its last checkpoint, on the same machine - for a run cut short by a machine that went away
copy hereone checkpoint copied to ~/pinkrab/train/<run>/checkpoints/<step>/pretrained_model; marked here when it is
copy each one herethe same for every checkpoint, as it is saved, while the studio is up (and the ones missed, when it comes back)

A checkpoint here is on the policy page: Ask to see what it answers, Drive to run it on the arm.

The terminal

pinkrab-remote does the same on the same store: a source added there is on this page, a run started there is drawn here.

pinkrab-remote add gpu-box --line "ssh -i ~/.ssh/id_ed25519 -p 22 user@gpu.example.com" \
               --root "~/pinkrab-train"
pinkrab-remote probe gpu-box
pinkrab-remote launch gpu-box blocks-left-v2-g2 --policy act --steps 100000
pinkrab-remote runs                   # id, state, progress, loss, checkpoints
pinkrab-remote fetch <id> --all
pinkrab-remote stop <id>
pinkrab-remote resume <id>

A run started by hand is shown too when it is started with pinkrab-train in place of lerobot-train - the same arguments - under a source's root.

Trouble

Permission denied (publickey)the machine does not take this key: the source's key, or the machine's authorized_keys
a source's error in the header, no answerthe machine is off, or its host or port changed: edit the source
cannot train here on testthe driver or the GPU is short of what the lock's PyTorch needs - see A remote machine
a run quietits process or its machine went away; with a checkpoint saved, Resume
checkpoints not arrivingcopies are made while the studio is up; the missed ones follow when it is up again
the first start is slowthe venv is being built on the machine, once; the strip says so
